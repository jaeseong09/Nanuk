**MySQL 접속 설정이 낯선 초보 개발자를 위한 CLI 도구입니다.**

“접속 정보는 어디에 적지?”, “왜 DB에 연결되지 않지?”라는 막막함을 줄여줍니다. 접속 정보를 입력하면 `.env`를 준비하고, 실제 연결을 확인해 실패할 때 확인할 곳을 한국어로 안내합니다.

- **`nanuk init`** — 질문에 답하며 접속 설정 준비하기
- **`nanuk doctor`** — 설정과 MySQL 연결 확인하기
- **`nanuk create-db`** — SQL을 확인하고 DB 생성하기
- **`nanuk preview`** — 스키마를 검사하고 SQL 미리보기
- **`nanuk create-table`** — SQL을 확인하고 테이블 생성하기

테이블 미리보기·생성은 0.3.0부터, 여러 테이블 지원은 0.4.0부터 제공합니다. [스키마로 테이블 만들기](#스키마로-테이블-만들기)에서 예시와 사용법을 확인하세요.

> **0.5.0부터 외래키 지원:** `ref users.id` 문법으로 테이블을 연결할 수 있습니다. [외래키로 테이블 연결하기](#외래키로-테이블-연결하기)를 참고하세요.

[npm에서 최신 버전을 설치할 수 있습니다](https://www.npmjs.com/package/nanuk-cli). 소스 코드는 [GitHub](https://github.com/jaeseong09/Nanuk)에서 확인하세요.

## 실행 흐름 한눈에 보기

MySQL 서버와 사용할 DB·계정이 준비된 상황의 예시입니다. 새 DB가 필요하면 아래 사용 방법의 `create-db` 단계를 먼저 진행하세요. Nanuk을 설치한 뒤, 설정을 저장할 프로젝트 폴더에서 실행합니다. 계정과 DB 이름은 본인 환경에 맞게 입력하세요.

```text
$ nanuk init
초기 설정을 시작합니다.
.gitignore를 생성하고 .env 제외 규칙을 추가했습니다.
MySQL 주소를 입력해 주세요 (기본값: 127.0.0.1):
PORT 번호를 입력해주세요 (기본값: 3306):
MySQL 사용자 이름을 입력해 주세요: app_user
사용할 데이터베이스 이름을 입력해 주세요. 예: board_db: board_db
```

이어서 비밀번호를 입력합니다. 입력 문자는 화면에 표시되지 않으며, 완료되면 다음 안내가 나옵니다.

```text
.env 파일을 생성했습니다.
DB_USER, DB_PASSWORD, DB_NAME을 확인하고 nanuk doctor를 실행해 주세요.

$ nanuk doctor
DB 검사를 시작합니다
DB 연결 성공
```

주소와 포트는 엔터를 누르면 기본값을 사용합니다. DB 이름에는 기본값이 없으며, `board_db`는 예시입니다.

## 시작하기

### 준비할 것

- **Node.js 22.x는 22.13.0 이상, 또는 Node.js 24 이상**과 npm
- 실행 중인 MySQL 서버
- MySQL에 접속 가능한 계정. 새 DB를 만들 때는 해당 DB의 CREATE 권한
- 기존 DB를 사용하거나, `create-db`로 새 DB를 생성

Nanuk은 접속 설정·DB 생성·연결 진단을 지원합니다. MySQL 설치와 계정 생성은 직접 준비해야 합니다. Docker로 실행한 MySQL도 호스트에 공개한 주소·포트로 접속할 수 있습니다.

### 바로 써보기

설정을 저장할 프로젝트 폴더에서 실행하세요. 전역 설치 없이 시작할 수 있습니다. npm이 패키지 다운로드 여부를 물으면 확인해 주세요.

```bash
npx nanuk-cli init
# DB가 아직 없다면 실행 (이미 있으면 건너뛰기)
npx nanuk-cli create-db
npx nanuk-cli doctor
```

### 계속 사용할 때: 설치하기

```bash
npm install -g nanuk-cli
nanuk --help
```

**설치할 패키지 이름은 `nanuk-cli`, 설치 후 실행 명령은 `nanuk`입니다.**

이미 `npm install nanuk-cli`로 프로젝트 안에 설치했다면 그 폴더에서 `npx nanuk init`처럼 실행하세요.

## 사용 방법

### 1. 접속 설정 준비하기

설정을 사용할 폴더로 이동해서 실행합니다.

```bash
nanuk init
```

| 입력 항목 | 입력 방법 |
| --- | --- |
| 주소 | 기본값 `127.0.0.1`. 다른 서버라면 해당 주소 입력 |
| 포트 | 기본값 `3306`. `1`~`65535` 사이의 정수 |
| 사용자 이름 | MySQL 계정 이름. 반드시 입력 |
| DB 이름 | 사용할 데이터베이스 이름. 반드시 입력. `create-db`를 쓸 때는 새로 만들 이름도 가능 |
| 비밀번호 | 해당 계정의 비밀번호. 비밀번호 없는 계정은 엔터 |

현재 폴더에 `.env`를 만들고 `.gitignore`에 `.env` 제외 규칙을 준비합니다. 기존 `.env`가 있으면 질문하지 않고 그대로 보존합니다.

어느 질문에서든 **Ctrl+C로 취소**할 수 있습니다. 취소하면 새 `.env`는 만들지 않습니다. 질문 전에 준비한 `.gitignore`는 남을 수 있습니다.

### 2. DB가 없다면 생성하기

**`create-db`는 0.2.0부터 제공됩니다.** 이전 버전이라면 먼저 업데이트하세요. 이미 DB가 있다면 이 단계를 건너뛰고 `doctor`로 확인하세요.

먼저 `init`으로 접속 정보를 준비합니다. `DB_NAME`에는 만들 이름을 입력하세요. 현재 `init`의 마지막 메시지는 `doctor`를 안내하지만, 새 DB를 만드는 경우에는 생성부터 진행합니다.

설정 폴더에서 실행하세요:

```bash
nanuk create-db
```

Nanuk 소스 폴더 자체에서 연습한다면 `node cli.js create-db`로 실행할 수 있습니다. 이 경우 소스 폴더의 `.env`를 읽습니다. `create-database.js` 파일을 직접 실행하는 방식은 사용하지 않습니다.

다음은 생성 권한이 있는 계정으로 새 DB를 만드는 예시입니다.

```text
생성할 DB: board_db
CREATE DATABASE `board_db` CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci
이 DB를 생성할까요? (y/N):y
DB를 생성했습니다: board_db
```

**출력한 SQL은 `y`에 동의하면 실제 MySQL 서버에서 실행됩니다.** 계정에 대상 DB의 `CREATE` 권한이 있어야 합니다. 생성 후 같은 설정 폴더에서 `nanuk doctor`로 접속을 확인하세요.

- DB 이름은 영문·숫자·밑줄(`_`)만 사용하며, 1~64자여야 합니다. Nanuk에서 정한 제한입니다.
- 주소·포트·사용자·DB 이름을 검사한 뒤 SQL을 보여줍니다. 포트는 `1`~`65535` 사이 정수여야 합니다.
- 답의 앞뒤 공백과 대소문자는 무시합니다. `y` 또는 `Y`만 진행하며, 엔터를 포함한 다른 답은 취소합니다.
- 질문 중 Ctrl+C를 누르면 생성하지 않고 취소합니다.
- 기존 DB는 삭제하거나 덮어쓰지 않습니다. 이미 존재하면 안내하고 종료합니다.
- 생성할 DB의 기본 문자셋은 `utf8mb4`, 정렬 규칙은 `utf8mb4_unicode_ci`입니다.

| 생성 중 발생한 문제 | 안내하는 확인 사항 |
| --- | --- |
| 같은 이름의 DB 존재 | 이미 존재하는 DB 이름 안내 |
| 생성 권한 부족 | DB_USER 계정의 해당 DB에 대한 CREATE 권한 |
| 인증 실패 | 사용자 이름·비밀번호·접속 허용 설정 |
| 연결 거부 | MySQL 실행 여부·주소·포트 |
| 시간 초과 | 주소·포트·네트워크·방화벽 |

접속 정보나 계정 권한을 자동으로 변경하지 않습니다. 위 항목 이외의 오류는 오류 코드를 출력합니다.

### 3. 연결 확인하기

`.env`가 있는 **같은 폴더**에서 실행합니다.

```bash
nanuk doctor
```

먼저 필수 설정과 포트를 검사하고, 통과하면 MySQL에 접속해 `SELECT 1`을 실행합니다. 쿼리가 성공한 뒤에만 연결 성공을 안내합니다.

`0.1.2`부터 누락되거나 공백만 있는 필수 설정을 한꺼번에 알려줍니다.

```text
필수 설정이 빠져 있습니다: DB_USER, DB_NAME
.env 또는 터미널 환경변수에 값을 설정해 주세요.
```

이 경우 DB 연결을 시도하지 않고 종료합니다. 안내된 값을 채운 뒤 다시 실행하세요.

| 연결 중 발생한 문제 | 안내하는 확인 사항 |
| --- | --- |
| 인증 실패 | 사용자 이름·비밀번호·계정의 접속 허용 설정 |
| 지정한 DB 없음 | DB 이름과 생성 여부 |
| 연결 거부 | 서버 실행 여부·주소·포트·Docker 포트 연결 |
| 응답 시간 초과 | 주소·포트·네트워크·방화벽 |

**상황에 따른 추가 안내** (`0.1.3`부터)

| 상황 | 추가 안내 |
| --- | --- |
| 비밀번호 없이 접속하다 인증 실패 | `DB_PASSWORD` 설정 확인 |
| MySQL 연결이 도중에 끊김 | 서버 상태 확인, 방금 재시작했다면 잠시 후 재시도 |
| `localhost`로 접속하다 연결 거부 | `DB_HOST`를 `127.0.0.1`로 바꿔 재시도 |

비밀번호를 사용하지 않았다는 단서만으로 `.env` 로딩 실패를 단정하지 않습니다. `localhost` 안내도 연결 거부가 발생했을 때만 추가합니다.

에러 코드는 확인할 곳을 좁히는 단서입니다. 인증 실패가 항상 비밀번호 오류인 것처럼 원인을 단정하지 않습니다.

### 4. 도움말 보기

```bash
nanuk --help
```

`nanuk -h` 또는 명령어 없이 `nanuk`만 실행해도 사용법을 볼 수 있습니다.

## 스키마로 테이블 만들기

아래는 **0.5.0 기준**입니다. 단일·여러 테이블 모두 **파일 작성 → SQL 미리보기 → 확인 후 생성** 순서로 진행합니다. 이전 버전이라면 `npm install -g nanuk-cli@0.5.0`으로 업데이트하세요. 전역 설치 없이 실행할 때는 아래 명령의 `nanuk` 대신 `npx nanuk-cli@0.5.0`을 사용하세요.

### 1. schema.nanuk 작성하기

명령을 실행할 폴더에 `schema.nanuk` 파일을 직접 만듭니다. `init`은 이 파일을 생성하지 않습니다.

#### 단일 테이블 예시

```text
table posts {
  id auto
  title varchar(100) NOT NULL
  content text
}
```

이 예시는 `posts` 테이블에 자동 증가 기본키 `id`, 필수 제목 `title`, 선택 본문 `content`를 정의합니다. 한 줄에 컬럼 하나를 적으며 쉼표나 세미콜론은 붙이지 않습니다.

| 문법 | 의미 |
| --- | --- |
| `table posts {` | 만들 테이블 이름. `table`, 이름, `{` 사이에는 공백 필요 |
| `id auto` | `INT AUTO_INCREMENT PRIMARY KEY`. 테이블당 최대 하나 |
| `title varchar(100) NOT NULL` | 최대 100자 문자열, NULL 허용 안 함 |
| `content text` | 본문용 문자열, NULL 허용 |
| `}` | 마지막 내용 줄에 단독으로 작성 |

`NOT NULL`은 SQL의 NULL 값을 막습니다. 빈 문자열까지 막는 입력 검사는 아닙니다.

#### 여러 테이블 만들기

**여러 테이블 지원은 0.4.0부터 제공됩니다.** 위의 단일 테이블 예시도 같은 방식으로 사용할 수 있습니다.

`schema.nanuk`에 테이블을 순서대로 작성하세요. 각 테이블에는 컬럼이 하나 이상 필요하며, 닫는 `}`를 각각 단독 줄에 적습니다.

```text
table users {
  id auto
  name varchar(20) NOT NULL
}

table posts {
  id auto
  user_id int NOT NULL
  title varchar(100) NOT NULL
  content text
}
```

이 예시의 `user_id`는 일반 정수 컬럼입니다. 0.5.0부터는 [외래키 문법](#외래키로-테이블-연결하기)을 추가해 `users.id`와 연결할 수 있습니다. 컬럼 이름과 `auto` 중복 여부는 테이블마다 따로 검사하므로 위처럼 두 테이블에 각각 `id auto`를 쓸 수 있습니다.

테이블 이름 중복 검사는 대소문자를 구분합니다. `users`가 두 번 등장하면 거부하며, MySQL에서 이름을 구분하는 방식은 서버 설정에 따라 달라질 수 있습니다.

아래 미리보기·생성 명령은 두 예시에 공통으로 사용합니다.

### 2. preview로 SQL 확인하기

`schema.nanuk`를 저장한 폴더에서 실행합니다.

```bash
nanuk preview
```

단일 테이블 예시의 출력:

```sql
CREATE TABLE `posts` (
`id` INT AUTO_INCREMENT PRIMARY KEY,
`title` varchar(100) NOT NULL,
`content` text
);
```

`preview`는 파일을 검사하고 SQL만 출력합니다. **MySQL 접속이나 테이블 생성은 하지 않으며 `.env`도 필요하지 않습니다.** 문법이 잘못되면 오류를 안내하고 종료합니다. 줄 번호가 표시되는 오류는 빈 줄을 포함한 원본 파일 기준입니다.

여러 테이블 예시는 `users`, `posts` 순서로 SQL을 출력합니다. **모든 테이블의 검사가 통과해야 SQL을 출력**하며, 오류가 있으면 일부 SQL도 출력하지 않습니다.

### 3. create-table로 실제 생성하기

같은 폴더에 접속 설정을 준비하세요. `DB_NAME`은 이미 존재하는 DB여야 하며, 계정에는 대상 DB 또는 테이블에 대한 `CREATE` 권한이 필요합니다. 새 DB가 필요하면 먼저 `nanuk create-db`로 만드세요.

```bash
# 접속 확인
nanuk doctor

# SQL 확인 후 테이블 생성
nanuk create-table
```

`create-table`은 접속 설정과 전체 스키마를 검사하고 생성할 SQL을 모두 보여줍니다. 이어서 아래 질문에 답합니다.

```text
이 테이블을 생성할까요? (y/N):
```

- **한 번의 `y` 또는 `Y` 응답으로 표시된 테이블 전체의 생성을 승인합니다.** 답의 앞뒤 공백은 무시하며, 파일에 적힌 순서대로 SQL을 하나씩 실행합니다.
- 엔터나 다른 답은 생성하지 않고 취소합니다. 확인 질문 중 Ctrl+C로도 취소할 수 있습니다.
- 모든 테이블 생성이 성공하면 `테이블을 모두 생성했습니다.`라고 안내합니다.
- 같은 이름의 테이블이 있으면 오류로 종료합니다. 기존 테이블을 덮어쓰거나 구조를 수정하지 않습니다.

| 발생한 문제 | 확인할 곳 |
| --- | --- |
| schema.nanuk 파일 없음 | 명령을 실행한 폴더와 파일 이름 |
| 스키마 문법 오류 | 안내된 줄의 이름·타입·옵션 |
| 같은 이름의 테이블 존재 | 기존 테이블을 사용할지, 새 이름으로 만들지 결정 |
| 지정한 DB 없음 | `DB_NAME` 확인 또는 `create-db`로 DB부터 생성 |
| 인증 실패 | `DB_USER`, `DB_PASSWORD`, 계정 접속 허용 설정 |
| 테이블 생성 권한 부족 | 계정의 대상 DB 또는 테이블에 대한 `CREATE` 권한 |
| 연결 거부·시간 초과 | MySQL 실행 상태·주소·포트·네트워크 |

### 중간 실패와 취소

생성은 테이블별로 진행됩니다. **중간에 실패해도 앞에서 생성된 테이블은 DB에 남습니다.** 예를 들어 `users` 생성 후 `posts` 생성이 실패하면 성공한 테이블 1개를 안내하고 오류 원인을 출력합니다. 이후 테이블 생성은 중단됩니다.

| 상황 | 동작과 안내 |
| --- | --- |
| 확인 질문에서 엔터 또는 `y` 이외의 답 | 생성 취소, 종료 코드 0 |
| 확인 질문·연결 대기 중 Ctrl+C | SQL 실행 전에 취소, 종료 코드 130 |
| 첫 테이블 성공 후 다음 SQL 전에 취소 | 성공 개수를 안내하고 다음 SQL을 실행하기 전에 중단 |
| SQL 실행 중 취소 후 성공 응답 수신 | 성공 개수에 반영하고 다음 SQL 전에 중단. 마지막 SQL이면 전체 성공 안내 |
| SQL 실행 중 취소와 오류가 겹침 | 앞서 확인된 성공 개수와 현재 생성 여부를 확인할 수 없다는 안내 |
| 취소 없이 생성 오류 발생 | 성공 개수와 오류 원인을 안내하고 종료 코드 1 |

Ctrl+C 요청이 있으면 종료 코드는 130입니다. 실행 중인 SQL은 취소 요청만으로 되돌릴 수 없으며, 연결 오류로 응답을 받지 못하면 DB에서 생성 여부를 확인해야 합니다. 성공한 테이블이 0개이면 개수 안내는 생략합니다.

다시 시도하기 전 DB의 테이블 목록을 확인하고, 이미 생성된 테이블을 고려해 스키마를 수정하세요. 기존 테이블을 자동으로 건너뛰거나 전체 작업을 롤백하는 기능은 아직 없습니다.

### 지원하는 스키마 범위

- 파일 하나에 테이블을 하나 이상 작성하고, 각 테이블에 컬럼을 하나 이상 작성합니다. 빈 줄과 들여쓰기는 허용합니다.
- 타입은 소문자 `auto`, `int`, `text`, `varchar(n)`만 지원합니다. `varchar(100)`처럼 괄호 안에 공백 없이 숫자를 적습니다.
- 옵션은 `NOT NULL`과 `ref 테이블명.컬럼명`을 지원하며 키워드의 대소문자는 구분하지 않습니다. 일반 컬럼은 `NOT NULL`이 없으면 NULL을 허용하고, `auto`는 기본키이므로 NULL을 허용하지 않습니다.
- 이름은 1~64자이며 공백을 포함할 수 없습니다. NUL 문자와 BMP 밖 문자(예: 많은 이모지)를 거부합니다. 컬럼 이름은 대소문자를 구분하지 않고 중복 검사합니다.
- 이름은 SQL 식별자로 감싸지만, MySQL의 모든 이름 제약을 미리 검사하지는 않습니다. 최종 생성 가능 여부는 MySQL에서 확인됩니다.
- `varchar(n)`은 기본적으로 0~65535 범위를 검사합니다. 실제 가능한 길이는 문자셋과 전체 행 크기에 따라 더 작을 수 있어, 미리보기에 성공해도 DB 생성 단계에서 거부될 수 있습니다.
- 생성 SQL에 문자셋·정렬 규칙을 따로 지정하지 않으므로 대상 DB의 기본값을 사용합니다.
- 외래키는 0.5.0부터 지원합니다. 참조 대상·자료형·선언 순서 제한은 [외래키 안내](#외래키로-테이블-연결하기)를 참고하세요.
- 주석 문법, 기본값, 별도 UNIQUE·인덱스, 시간 타입, 기존 테이블 변경·마이그레이션은 아직 지원하지 않습니다.

### 로컬 소스로 개발할 때

로컬 개발 소스를 명령으로 연결하려면 **Nanuk 소스 폴더에서** 한 번 실행합니다.

```bash
npm link
```

그다음 `.env`와 `schema.nanuk`가 있는 프로젝트 폴더로 이동해 실행합니다.

```bash
nanuk preview
nanuk create-table
```

이때 `nanuk`은 npm 배포본이 아닌 연결한 로컬 소스를 실행합니다. 설정과 스키마는 Nanuk 설치 위치가 아니라 **현재 실행 폴더**에서 읽습니다. 스키마 경로를 인수로 지정하는 기능은 아직 없습니다.

## 외래키로 테이블 연결하기

**외래키는 0.5.0부터 지원합니다.** 이전 버전은 `npm install -g nanuk-cli@0.5.0`으로 업데이트하세요. 전역 설치 없이 실행하려면 아래 명령의 `nanuk` 대신 `npx nanuk-cli@0.5.0`을 사용하세요. `schema.nanuk`를 저장한 프로젝트 폴더에서 실행합니다.

### 스키마 작성과 미리보기

참조 대상인 `users`를 먼저 쓰고, `posts`의 컬럼 끝에 `ref users.id`를 붙입니다.

```text
table users {
  id auto
  name varchar(20) NOT NULL
}

table posts {
  id auto
  user_id int NOT NULL ref users.id
  title varchar(100) NOT NULL
  content text
}
```

`user_id int NOT NULL ref users.id`는 **필수 정수 컬럼 `user_id`가 `users`의 `id`를 참조한다**는 뜻입니다. `NOT NULL`을 생략하면 NULL을 허용하는 외래키 컬럼이 됩니다.

```bash
nanuk preview
```

출력:

```sql
CREATE TABLE `users` (
`id` INT AUTO_INCREMENT PRIMARY KEY,
`name` varchar(20) NOT NULL
);
CREATE TABLE `posts` (
`id` INT AUTO_INCREMENT PRIMARY KEY,
`user_id` int NOT NULL,
`title` varchar(100) NOT NULL,
`content` text,
FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE RESTRICT
);
```

### 실제 생성과 삭제 제한

같은 폴더의 `.env`에서 대상 DB를 지정한 뒤 실행합니다. DB는 이미 존재해야 하고, 예시 테이블 이름은 그 DB에서 사용 중이지 않아야 합니다.

```bash
nanuk doctor
nanuk create-table
```

전체 스키마의 관계 검사를 통과하면 SQL을 보여주고, `y` 확인 후 부모 테이블부터 생성합니다. 예전에 만든 `users`·`posts`가 있으면 중복 오류가 나며, 기존 테이블에 외래키를 추가하지는 않습니다. 연습할 때는 새 DB를 쓰거나 테이블 이름과 `ref` 대상을 함께 바꾸세요.

`ON DELETE RESTRICT`는 **글이 남아 있는 유저를 삭제하지 못하게 하는 규칙**입니다. 존재하지 않는 유저를 참조하는 글 작성·수정도 DB에서 거부됩니다. 글을 먼저 삭제하면 해당 유저를 삭제할 수 있습니다. 글을 자동 삭제하는 `CASCADE` 동작은 제공하지 않습니다.

현재 SQL은 스토리지 엔진을 명시하지 않습니다. 실제 외래키 검증은 **MySQL 9.3.0, InnoDB, `foreign_key_checks=1`**에서 수행했습니다. 다른 기본 엔진이나 외래키 검사 설정은 이번 검증 범위에 포함되지 않습니다. `doctor`의 연결 성공만으로 외래키 동작까지 검증되지는 않습니다.

### 지원 규칙과 오류 안내

| 규칙 | 작성 방법 |
| --- | --- |
| 문법 | 컬럼 끝에 `ref 테이블명.컬럼명`을 한 번만 작성 |
| NULL 허용 여부 | 필수 값이면 `NOT NULL`을 `ref` 앞에 작성 |
| 참조 범위 | 같은 파일에 선언된 테이블·컬럼만 참조. 기존 DB의 테이블을 자동 조회하지 않음 |
| 자료형 | 참조하는 컬럼은 `int`, 대상은 `auto` 기본키 |
| 선언 순서 | 부모 테이블을 자식보다 먼저 작성. 자동 정렬·자기 참조·순환 참조 미지원 |
| 대소문자 | `ref`와 `NOT NULL` 키워드는 구분하지 않음. 참조 대상 이름은 선언과 대소문자까지 일치해야 함 |
| 이름 구분 | 점 하나로 테이블과 컬럼을 나누므로 점이 들어간 이름을 참조하는 문법은 미지원 |
| 삭제 규칙 | `ON DELETE RESTRICT`로 고정. 별도 삭제·수정 규칙을 지정하는 문법은 없음 |

이 제한은 Nanuk의 현재 지원 범위이며 MySQL 전체의 기능 제한을 뜻하지 않습니다. 한 테이블에 여러 외래키 컬럼을 작성할 수 있지만, 여러 컬럼을 묶는 복합 외래키는 지원하지 않습니다.

잘못된 참조 문법, 없는 테이블·컬럼, 자료형 불일치, 선언 순서 오류는 SQL 출력 전에 종료 코드 `1`로 중단합니다. `create-table`도 같은 검사를 수행하며, 실패하면 확인 질문이나 DB 접속을 진행하지 않습니다. 문법 오류는 원본 줄 번호를, 관계 오류는 `posts.user_id`처럼 해당 테이블·컬럼을 안내합니다.

```text
posts.user_id: 참조할 테이블 'members'이 스키마에 없습니다.
posts.user_id: 현재 외래키 컬럼은 int 자료형만 사용할 수 있습니다.
```

실제 생성 중 오류가 나면 앞에서 생성한 테이블은 남습니다. [중간 실패와 취소](#중간-실패와-취소)의 안내에 따라 DB 상태를 확인하세요.

## 현재 범위와 제한

- 접속 설정 준비·확인 후 DB 생성·연결 진단을 지원합니다.
- **0.3.0부터:** 단일 테이블 스키마의 SQL 미리보기와 확인 후 테이블 생성을 지원합니다.
- **0.4.0부터:** 여러 테이블 미리보기·순차 생성·중복 이름 검사·중간 실패 및 취소 시 성공 개수 안내를 추가했습니다.
- **0.5.0부터:** `int` → `auto` 외래키 문법, 참조 대상·순서 검사, `ON DELETE RESTRICT` SQL 생성을 지원합니다.
- MySQL 설치, 계정 생성, Express·React 코드 생성은 지원하지 않습니다.
- 연결 성공은 지정한 DB에서 `SELECT 1`이 성공했다는 뜻입니다. 테이블 구조, 쓰기 권한, 문자셋·시간대, CORS까지 확인하지는 않습니다.
- 설정값을 자동으로 고치지는 않습니다. 안내를 확인한 뒤 직접 수정해 주세요.
- `.env`에는 비밀번호가 평문으로 저장됩니다. 입력을 숨기는 것과 파일을 암호화하는 것은 다릅니다. `.env`를 공유하거나 커밋하지 마세요.

## 설정과 동작 상세

### 설정을 읽는 위치

`doctor`는 **명령을 실행한 현재 폴더**의 `.env`를 읽습니다. 예를 들어 설정이 `server/`에 있다면 그 폴더로 이동해서 실행하세요. 하위 폴더를 자동으로 탐색하지 않습니다.

접속 설정은 `doctor`와 `create-db`, `create-table` 실행 시 읽습니다. `preview`는 접속 설정을 읽지 않습니다. `init`과 도움말 실행 시에는 접속 설정을 로드하지 않으며, dotenv 자체의 로딩 안내 로그도 숨깁니다.

`doctor`는 `.env`가 없으면 안내 후 터미널 환경변수로 검사를 계속합니다. `create-db`와 `create-table`도 터미널 환경변수를 사용할 수 있지만 파일 부재 안내는 따로 출력하지 않습니다. 터미널에 이미 설정한 값은 기본적으로 `.env`보다 우선합니다.

| 환경변수 | 의미 | 필수 여부 |
| --- | --- | --- |
| `DB_HOST` | MySQL 서버 주소 | 필수 |
| `DB_PORT` | MySQL 접속 포트 | 필수 |
| `DB_USER` | MySQL 계정 이름 | 필수 |
| `DB_NAME` | 사용할 DB 이름 | 필수 |
| `DB_PASSWORD` | 계정 비밀번호 | 빈 비밀번호 허용 |

`doctor`는 필수 값이 없거나 빈 문자열·공백만 있으면 누락으로 판단합니다. 다른 환경변수 이름을 자동으로 인식하지는 않습니다.

### 비밀번호 저장과 Git 제외 처리

- 비밀번호의 앞뒤 공백은 제거하지 않습니다. 한 줄 비밀번호를 대상으로, `.env`로 저장한 뒤 dotenv가 원래 값으로 읽을 수 있는지 검사합니다.
- 원본을 보존할 수 없는 문자 조합은 저장하지 않고 안내합니다. 예를 들어 작은따옴표·큰따옴표·백틱이 모두 들어 있는 조합은 현재 지원하지 않습니다.
- `.gitignore`의 기존 내용은 유지하며 정확한 `.env` 줄이 없을 때 추가합니다. 복잡한 제외·예외 패턴을 해석하거나 이미 Git이 추적 중인 파일을 추적 해제하지는 않습니다.

### 종료 코드

`preview`와 `create-table`은 0.3.0 이상 기준입니다.

| 코드 | 의미 |
| --- | --- |
| `0` | 정상 완료, 도움말 표시, 기존 `.env` 보존 또는 `create-db`·`create-table` 확인 질문에서 일반 취소 |
| `1` | 잘못된 명령어, 설정 오류, 연결·DB/테이블 생성 실패, 스키마 오류 또는 파일 처리 실패 |
| `130` | `init`·`create-db` 질문 중 Ctrl+C, 또는 `create-table`의 Ctrl+C 요청 (실행 후 생성 여부는 출력 확인) |

| `test/create-table.test.js` | 13 | 생성·취소·부분 성공·실패 이후 중단 |
| `test/foreign-key.test.js` | 17 | 외래키 SQL, 여러 외래키, 이름 보존, 참조 문법·대상·자료형·순서 오류 |

`npm test`는 실제 MySQL 서버 없이 실행할 수 있습니다. 생성·취소 검사는 입력·DB 대역을 사용하고, 외래키 검사는 임시 스키마로 실제 CLI를 실행합니다. 외래키 오류 14종은 `preview`와 `create-table` 양쪽에서 확인합니다.

실제 DB에서는 MySQL 9.3.0/InnoDB에서 테이블 생성, 정상 참조, 잘못된 참조의 INSERT·UPDATE 차단, 참조 중인 부모의 DELETE·기본키 UPDATE 차단을 별도로 검증했습니다. 이 DB 실험은 `npm test`에 포함되지 않습니다.

자세한 결과와 학습 중 막힌 부분은 [개발 기록](https://github.com/jaeseong09/Nanuk/blob/main/DEVELOPMENT_LOG.md)에 남깁니다. 이 기록 파일은 npm 패키지에는 포함되지 않습니다.

로컬 실행 확인에 사용한 Node.js 버전은 22.19.0과 25.9.0입니다. 이는 지원 범위에 속한 모든 버전을 테스트했다는 뜻은 아닙니다.
